# Протокол FNIRSI DPS-150

Источники: реверс-инжиниринг cho45 (github.com/cho45/fnirsi-dps-150, `dps-150.js`
и `docs/FNIRSI_DPS-150_Protocol.md`), PyPI-пакет `fnirsi-dps150` (проверен его
автором на реальном приборе под macOS) и philipp-iot.github.io/fnirsi_protocol.
Реализация в этом проекте: `Sources/DPS150Kit/Protocol.swift`.

## Физический уровень

- USB CDC ACM через **micro-USB** порт данных; Type-C на приборе только для питания.
- VID:PID `2E3C:5740` (Artery AT32). На macOS порт выглядит как `/dev/cu.usbmodem*`.
  Использовать `cu.*`, а не `tty.*`: `tty.*` блокируется на open.
- 115200 8N1, без аппаратного управления потоком. Скорость в протоколе выбирается
  командой `B0`, мы всегда шлём индекс 5 (115200). Один источник упоминает 9600
  и DTR=off/RTS=on, но pyserial с настройками по умолчанию работает.

## Формат кадра

```
[HDR] [CMD] [REG] [LEN] [DATA × LEN] [CHK]
HDR  = 0xF1 хост→прибор, 0xF0 прибор→хост
CHK  = (REG + LEN + sum(DATA)) & 0xFF      # CMD и HDR в сумму не входят
float — IEEE-754 float32 little-endian
```

| CMD  | Назначение |
|------|-----------|
| `A1` | GET (запрос) — и **все** ответы/телеметрия прибора приходят с CMD=A1 |
| `B1` | SET (запись регистра) |
| `B0` | выбор скорости: DATA = индекс в [9600, 19200, 38400, 57600, 115200] + 1 |
| `C1` | сессия: DATA = 1 открыть, 0 закрыть |

GET отправляется с одним байтом данных `00`: `F1 A1 <reg> 01 00 <chk>`.

## Сессия

1. `F1 C1 00 01 01 02` — открыть сессию
2. `F1 B0 00 01 05 06` — 115200
3. GET 222, 223, 224 — модель и версии
4. GET 255 — полный дамп
5. дальше прибор **сам** шлёт C0, C3, C4, E2, E3 примерно каждые 500 мс, а при
   изменении — DB, DC, DD. Подтверждать телеметрию не нужно.
6. При выходе: `F1 C1 00 01 00 01`.

Вендорский софт после каждой записи делает GET 255 и держит между кадрами паузу
около 50 мс. Мы делаем так же (`Device.writeGap`) и вдобавок раз в 2 с
запрашиваем дамп, чтобы ловить изменения, сделанные ручкой на приборе.

## Проверено на реальном приборе (2026-11-12, железо V1.0, прошивка V1.2)

Чтение: сессия, GET 222/223/224/255 и 2.5 с телеметрии, без ошибок контрольной суммы.

- Дамп ровно 139 байт, раскладка из таблицы выше верна (уставки, пресеты,
  пороги, яркость/громкость, счётчик, выход, защита, режим, пределы).
- Телеметрия C0, C3, C4, E2, E3 приходит каждые 500 мс без запросов.
- E2 (макс. напряжение) = Vin − 0.2 В.
- C3 при выключенном выходе и подключённой банке показывает напряжение банки
  (3.98 В), ток и мощность — 0.
- Без питания на Type-C прибор запитывается от банки на выходе: Vin ≈ 3.4 В,
  код защиты 5 (LVP, порог 5.0 В), зарядить ничего нельзя. Приложение в этом
  случае заряд не начинает.
- Запись уставок, OVP и включение счётчика (D8) из нативного приложения дошли
  до прибора и видны в дампе.
- Полный цикл заряда Li-ion банки с питанием на входе (2026-11-16).
